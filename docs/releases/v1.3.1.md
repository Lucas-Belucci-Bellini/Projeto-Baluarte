## Escopo

A release 1.3.1 adiciona ao módulo V2 Evidence uma projeção local `retentionPreview(options)`. O recurso mede a idade de registros observados com uma data `now` explícita e classifica cada item como `within-window`, `past-window` ou `future-observed`. Ele existe para preparar decisões futuras de retenção e auditoria sem apagar, alterar, verificar ou promover evidências.

A API usa `maxAgeDays` padrão 30, teto 3650, `limit` padrão 25 e teto 100. Argumentos inválidos lançam `TypeError`. A saída é congelada e contém apenas `now`, `maxAgeDays`, itens redigidos e resumo bounded. Cada item contém somente `id`, `moduleId`, `status`, `observedAt`, `ageDays` e `retention`; statement, source, URI, publisher, collector, confidence, claimKey, tokens, claims e permissões são omitidos.

O preview não apaga registros, não modifica status e não adiciona rota ou permissão. O fallback sem Evidence ou após `dispose` é um preview vazio depois da validação das opções. A implementação canônica permanece em TypeScript, o wrapper JavaScript é preservado e a API é registrada no módulo Evidence existente.

## Segurança e limites

Este marco é local, in-memory e read-only. Não há rede, scraping, worker, banco remoto, Supabase, SQL, RLS, Auth, OpenClaw, WhatsApp, Spotify, publicação automática ou uso de segredos. A política `runtimeAuthority: not-authorized` e `publicPromotionAllowed: false` permanece intacta.

A projeção não é uma política de descarte e não é uma autorização de revisão humana. Persistência, retenção operacional, auditoria, tenancy, concorrência, revisão server-side e rollback continuam fora desta release.

## Rollback

A referência operacional anterior é a release pública `v1.3.0`. Antes das tags, um problema deve ser revertido por commit novo sem reescrever a história. Depois de publicada, o rollback operacional deve retornar à `v1.3.0` e usar uma nova chave de Service Worker em qualquer correção posterior; a chave `baluarte-v1.3.1` não deve ser reutilizada para conteúdo diferente.

## Próximo passo V2

Depois deste preview, o próximo passo válido é definir retenção operacional e auditoria de consumidor para Evidence local, com limites de idade, duplicidade, concorrência e descarte. Persistência Supabase/RLS só poderá ser considerada com aprovação explícita de staging, custo, migration, tenancy e rollback.
