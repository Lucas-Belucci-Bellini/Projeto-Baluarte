## Resumo

A `v2.0.0-alpha.2` integra o cliente `server-observation-http/v1` à UI do modo Servidor do JARVIS. O operador pode testar um endpoint controlado e receber uma projeção bounded de conexão, health, fallback e motivo de indisponibilidade. A observação continua explicitamente não autorizada; este marco não declara a V2 estável e não substitui a V1.

## Incluído

O adapter resolve somente endpoints controlados. Em HTTPS com `serverUrl` vazio, usa o adapter same-origin `/api/observability`; em desenvolvimento ou servidor explicitamente configurado, usa `/observability/observe`. URLs inválidas, com credenciais, query string ou fragmento não executam rede.

A requisição é GET, sem body e com timeout bounded. O resultado não propaga URL, headers, token, corpo HTTP, subject, role, metadata ou mensagem arbitrária de exceção. HTTP 429, outros erros HTTP, timeout, falha de rede, JSON inválido e endpoint ausente são convertidos em estados conservadores.

O botão `Testar conexão` do JARVIS agora usa essa projeção, sem alterar os demais modos de conversa. O wrapper JavaScript garante que o cliente canônico também possa ser executado pelos testes nativos do Node 24. O filtro do workflow Security Contracts passou a observar `src/security/**`, e ganhou acionamento manual para reexecução controlada.

## Limites alpha

Este marco não implementa login, refresh, redirect, logout, Supabase Auth, RLS, tenancy, claims de autoridade, roles, retry automático, cache, persistência ou promoção operacional. `authority` permanece `not-authorized`, `publicPromotionAllowed` permanece `false` e nenhuma observação habilita módulos ou altera `runtimeAuthority`.

O `Supabase Preview` ficou `skipped` por política do repositório; nenhuma migration ou escrita remota foi executada. O warning de chunks grandes no build permanece conhecido e não reprova o gate.

## Rollback

O rollback retorna ao commit anterior da `main` (`ae516f1`, alpha.1 documental) ou à branch de backup [`backup/2026-08-25-before-v2-auth-ui`](https://github.com/Lucas-Belucci-Bellini/Projeto-Baluarte/tree/backup/2026-08-25-before-v2-auth-ui). Em termos funcionais, remova o import/uso no botão do JARVIS, o adapter UI, o wrapper, seus testes e as entradas documentais; os endpoints backend, a V1 e a projeção server-validated permanecem intactos.

## Próximo marco sugerido

O próximo trabalho de Auth deve ser um contrato separado para refresh/redirect real, com identidade, expiração, tenancy, ownership, concorrência, rollback e revisão server-side explicitamente aprovados. Até essa decisão, a UI deve permanecer observadora e não autorizada.
