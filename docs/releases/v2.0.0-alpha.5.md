## Resumo

A `v2.0.0-alpha.5` adiciona um benchmark offline e reprodutível para o Event Bus V2. O comando `npm run bench:event-bus` exercita `criarBus().emit()` em três cargas de ouvintes, aquece o JIT, confere a entrega de todos os handlers e verifica que `bus.saude().latencia.n` acompanha as emissões.

O resultado observado no sandbox Linux foi de **9,460 a 10,103 µs por despacho externo** em 20.000 operações por cenário, com média interna arredondada de `0,01 ms`. A medição é evidência local de custo, não uma promessa de hardware nem um threshold de produção.

## Limites alpha

A V2.0.0 estável ainda não foi declarada. Esta release não cria threshold de produção, alerta, percentil, retry, backpressure, persistência, rede, storage, banco, Supabase, RLS, tenancy, ownership, revisão humana server-side, Auth real, logout, autoridade ou promoção operacional.

Os números variam com máquina, versão do Node, scheduler e carga do processo. O benchmark não deve ser usado para comparar hardware sem repetir o método e registrar o ambiente. A V1 e os contratos V2 anteriores permanecem preservados.

## Rollback

O rollback retorna ao commit anterior da `main` (`7e6e513`, gate documental de ownership/retention) ou à branch de backup [`backup/2026-08-25-before-v2-event-bus-benchmark`](https://github.com/Lucas-Belucci-Bellini/Projeto-Baluarte/tree/backup/2026-08-25-before-v2-event-bus-benchmark). A reversão remove o script, o comando, o registro de resultado e o contrato do benchmark, sem alterar o Event Bus publicado na alpha.4.

## Próximos bloqueios

A política de retry por classe de evento continua sem decisão e não será inventada a partir deste benchmark. Ownership, retenção operacional, revisão humana server-side, persistência Supabase/RLS, Auth real e performance em hardware de usuário continuam dependentes de contratos, staging, custo e rollback próprios.
