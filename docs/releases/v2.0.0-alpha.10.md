## Resumo

A `v2.0.0-alpha.10` adiciona uma busca local, determinística, bounded e read-only sobre as evidências já presentes no `EvidenceStore`. O objetivo é fechar parcialmente a lacuna oficial de search/index sem introduzir full-text, banco, índice persistente, rede, ranking ou autoridade.

A implementação é TypeScript-first e é exposta por `projectEvidenceSearch(records, options)`, `EvidenceStore.search(options)` e `evidence.api.search(options)`. O Wiki Zomboid não muda sua API pública e continua usando a fila legada de seis campos.

## Incluído

| Superfície | Resultado |
|---|---|
| Consulta | `query` obrigatório, trim e case-insensitive |
| Escopo | filtro opcional exato por `moduleId` |
| Estado | filtro opcional por `pending`, `verified`, `rejected` ou `superseded` |
| Metadados pesquisáveis | `id`, `claimKey`, `moduleId` e `source.revision` |
| Limite | padrão `25`, teto `100`, sem paginação implícita |
| Resumo | `returned`, `available` e `truncated` |
| Redaction | não retorna `statement`, URI, publisher ou collector |
| Segurança | projeção congelada, sem mutação, promoção ou autoridade |
| Documentação | contrato Evidence Search e README do Data Layer |

## Método

A consulta filtra em memória, preserva a ordem append-only do store e seleciona os primeiros `limit` matches. Não há score, stemming, fuzzy matching, normalização semântica ou índice externo. Quando o módulo ainda não foi inicializado, a API retorna uma projeção vazia e não cria store implícito.

A busca não procura no texto da afirmação. Essa decisão mantém a primeira versão estrutural e reduz a superfície de exposição de conteúdo e fontes; full-text e `pgvector` permanecem decisões futuras condicionadas a consulta real, benchmark, adapter e staging.

## Segurança e compatibilidade

A busca é observação local. Ela não autentica evidência, atribui ownership, resolve tenancy, autoriza revisão humana, altera status, grava banco ou concede permissões. `moduleId` continua sendo namespace produtor, não proprietário operacional.

As APIs de listagem, claim, módulo, retenção, auditoria e review queue permanecem compatíveis. A V1, a ponte de backup, Auth read-only, Runtime, Event Bus, Task Manager e Doctor não foram alterados neste slice.

## Limites alpha

A V2.0.0 estável ainda não foi declarada. A busca não é full-text, ranking, pgvector, index persistente, consulta remota, Knowledge Mesh completo, Evidence server-side, auditoria de produção ou mecanismo de retenção. O limite `100` protege apenas a projeção, não estabelece budget de produção.

Continuam bloqueados persistência Supabase/RLS, ownership/retenção/revisão humana server-side, Auth real, retry por classe de evento sem ADR, RPO/RTO de produção, runtime Rust em toolchain compatível e performance em hardware de usuário.

## Rollback

O rollback retorna ao commit anterior da `main` (`9b43cd3`, alpha.9) ou à branch de backup `backup/2026-08-26-before-v2-evidence-search`. A reversão remove a busca, testes e contrato sem tocar nas projeções anteriores, no backup local, na V1 ou em qualquer storage remoto.
