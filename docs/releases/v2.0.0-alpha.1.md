# Release `v2.0.0-alpha.1` — Runtime Group Observability

**Status:** publicada como pré-release
**Data do marco:** 2026-08-25
**Versão:** `2.0.0-alpha.1`
**Base:** `main` após o merge da PR #472

> Esta é a primeira release acompanhável da V2. Ela não declara a V2 estável nem substitui a V1. O objetivo é tornar visível uma fundação de Runtime que pode ser testada, observada e evoluída por marcos pequenos.

## O que entrou

A release fecha a composição observável do grupo de Runtime. O caminho agora reúne o `RuntimeManagerGroup`, o `RuntimeGroupLifecycle`, os eventos estruturados, o histórico de estado e o `RuntimeSupervisor` sem criar um segundo mecanismo de startup, readiness, rollback ou shutdown.

O contrato coletivo ganhou `status()` como projeção compatível com o supervisor. A superfície anterior `snapshot()` continua disponível e sem alteração de formato. Os hooks de eventos de grupo aceitam arrays somente leitura, alinhando o contrato JSDoc com os dados que o manager já produz.

A composição foi coberta por testes de sucesso, shutdown reverso, falha de readiness, rollback e redaction. Erros são convertidos em mensagens antes de entrar no histórico observável; stacks, closures e objetos `Error` não atravessam essa fronteira.

## Limites conhecidos

A release é **alpha**. O Event Bus ainda não possui política de retry por classe de evento; a matriz mantém essa decisão pendente para não inventar semântica de repetição. Persistência remota, Supabase, RLS, billing remoto, claims de autoridade e autorização operacional permanecem fora deste marco. O `Runtime` Rust continua sujeito ao bloqueio conhecido do ambiente local quando o gate exigir `edition2024`.

A composição está pronta como contrato e prova de integração, mas ainda não transforma o `RuntimeManagerGroup` em autoridade de produção nem libera módulos automaticamente. Observabilidade continua sendo read-only.

## Rollback

O rollback do marco é a reversão do merge da PR #472 na `main`. A V1, o router, o shell, Auth, RLS e os módulos de produto não foram alterados por esta release. A tag é uma pré-release de acompanhamento e não deve ser usada como baseline estável de produção.

## Próximo marco previsto

Continuar pela primeira fase pendente que possa ser executada sem credenciais ou staging remoto. O retry do Event Bus permanece bloqueado até existir uma política explícita; a próxima frente segura deve evoluir um contrato local já previsto na matriz, com testes e gates completos antes de outra release alpha.
