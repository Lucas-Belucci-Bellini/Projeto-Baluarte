## Escopo

A release 1.3.0 amplia o piloto V2 Wiki Zomboid/Evidence com `reviewQueue(limit)`, um read-model local, bounded e somente leitura para preparar uma revisão humana futura. A fila lê apenas `Evidence.listByModule('wiki-zomboid')`, filtra registros `pending`, usa limite padrão 25 e máximo 100 e congela a lista e cada item devolvido.

Cada item da fila contém somente `id`, `claimKey`, `status`, `confidence`, `observedAt` e `sourceRevision`. O contrato deliberadamente omite `statement`, `source`, URI, título, publisher, collector, `moduleId`, tokens, claims e permissões. A fila inicia vazia no boot limpo do harness. A API não adiciona `markStatus`; o teste usa a API do módulo Evidence exclusivamente para provar que um registro marcado como `verified` deixa de aparecer no read-model.

## Segurança e limites

O slice continua local, read-only e sem autoridade operacional. Não adiciona permissões, storage, rede, scraping, persistência, Auth, RLS, Supabase, OpenClaw, WhatsApp, Spotify ou publicação automática. Não existe UI de aprovação e nenhum usuário ou navegador pode alterar o status por meio do módulo Wiki.

A V1, o router, as 99 rotas do smoke, as superfícies `/zomboid` e `/zomboid-admin` e os wrappers JavaScript permanecem preservados. `runtimeAuthority` continua `not-authorized` e `publicPromotionAllowed` continua `false`. A revisão humana real, os roles administrativos, a auditoria de consumidor, a retenção e a persistência remota continuam fora deste marco e dependem de autoridade server-side, tenancy, RLS, staging e rollback aprovados.
