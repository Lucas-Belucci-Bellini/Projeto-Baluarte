# Release 1.2.6 — JARVIS Núcleo V7

**Status:** `PREPARAÇÃO — aguardando publicação dos artefatos desktop`

**Versão web:** `1.2.6`

**Versão do Launcher:** `1.2.6`

**Tag planejada do desktop:** `desktop-v1.2.6`

**Tag pública planejada:** `v1.2.6`

**Commit validado:** será preenchido após a publicação do commit final no `main`.

## Escopo

A release 1.2.6 promove o visual **JARVIS Núcleo V7 — Astrolábio Sonoro** como a experiência 3D canônica do projeto. A entrega preserva o shell V1, o router, as 99 rotas, a página de conversa `/jarvis` e os contratos da V2. O Núcleo V7 continua sendo uma entrada multipágina independente empacotada pelo Vite.

O visual V7 substitui a apresentação anterior do Núcleo por um objeto 3D com cristal, plasma, anéis, constelação, faíscas, pós-processamento de bloom, temas ouro/rubi/jade, rotação, vistas retrato/diagnóstico/órbita, varrimento, pulso e captura PNG. O motor de áudio reage a música generativa, ficheiros de áudio e microfone por Web Audio, com bandas grave/médio/agudo, deteção de batida e textura FFT enviada à GPU.

## Artefatos desktop esperados

A publicação da tag `desktop-v1.2.6` deve gerar, conforme a matriz existente do Launcher, instaladores para Windows, Linux e macOS, além dos blockmaps e manifestos de atualização. Os nomes e checksums finais serão registrados somente após o workflow concluir; nenhum tamanho ou URL será inventado antes da verificação HTTP 200.

## Compatibilidade e limites

A release não ativa Auth/RLS, Billing, OpenClaw, Spotify ou novas permissões. O microfone depende de permissão do navegador ou do sistema operacional. Música externa continua limitada às fontes que o navegador pode observar com segurança: música generativa interna, ficheiro selecionado e microfone; a captura direta do áudio privado de outro aplicativo não é prometida por esta release.

O entrypoint visual usa Three.js CDN e fontes externas declaradas no HTML. Em ambientes sem rede, a experiência pode iniciar sem esses recursos externos; isso deve ser tratado como limitação operacional conhecida, não como autorização para inserir secrets ou dependências não auditadas.

## Rollback

O rollback do código é retornar ao commit imediatamente anterior à promoção da 1.2.6. O rollback do desktop é não publicar a tag `desktop-v1.2.6` até os artefatos serem verificados; depois de publicada, a recuperação deve apontar para a última release validada, `v1.2.5`, sem apagar uma release correta para esconder documentação incompleta. O Service Worker volta a ser invalidado somente por uma nova versão corrigida, não por alteração manual de cache em produção.

## Critério de publicação

A 1.2.6 somente pode receber a tag pública quando o commit final estiver no `main`, todos os gates críticos estiverem verdes, a documentação estiver atualizada e o workflow desktop produzir artefatos reprodutíveis para Windows, macOS e Linux. Até lá, o progresso permanece no `main` sem declarar a release pública concluída.
