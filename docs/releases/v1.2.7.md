## Escopo

A release 1.2.7 promove o primeiro vínculo do vertical slice local Briefing→Evidence pelo caminho real de módulos V2. O manifesto do Briefing declara a referência fraca `references.modules: ['evidence']` e o lifecycle resolve `ctx.talvez('evidence', { versao: 1 })` pelo resolvedor governado do Core.

O harness V2 registra seis módulos ativos: Cripto, Editor, Militar, Evidence, Briefing e Visor 3D. Evidence permanece sem rota, de modo que as 19 rotas da V1 e os cinco itens de navegação continuam preservados. A superfície do Briefing mostra um indicador textual de Evidence local conectada, sem expor conteúdo de evidência, tokens ou autoridade operacional.

A release não adiciona rede, banco remoto, DDL, migration, RLS, Auth de produção, OpenClaw, WhatsApp, publicação automática, envio externo ou controle de reprodução. O fallback sem Evidence permanece suportado.

## Alterações de versão

A versão `1.2.7` é sincronizada em `package.json`, `package-lock.json`, `desktop/package.json`, `desktop/package-lock.json`, `src/data/version.js`, `public/sw.js` e no valor padrão informativo do workflow Desktop Release. O Service Worker usa `baluarte-v1.2.7` para invalidar caches anteriores.

## Artefatos desktop esperados

Depois que o commit de versão e o CI remoto estiverem verdes, a tag `desktop-v1.2.7` poderá acionar o workflow Desktop Release. A release só será considerada publicada quando os instaladores Windows, macOS ARM64 e Linux forem produzidos e a API de releases retornar a versão `v1.2.7` como pública e não-prerelease.

Os assets esperados são `Baluarte-Launcher-Setup-1.2.7.exe`, `Baluarte-Launcher-1.2.7.AppImage`, `Baluarte-Launcher-1.2.7-arm64.dmg`, os dois blockmaps e os manifestos `latest.yml`, `latest-linux.yml` e `latest-mac.yml`. Tamanhos e SHA-512 serão registrados somente após o workflow produzir os arquivos reais.

## Compatibilidade e limites

A release mantém o shell V1, o router, os wrappers JavaScript, a política deny-by-default, `runtimeAuthority: not-authorized` e `publicPromotionAllowed: false`. A Evidence Layer continua local, append-only e começando em `pending`; o vínculo não transforma candidatos de notícias em fatos verificados nem concede permissões a usuários.

O runtime Rust local pode continuar retornando código 101 quando o Cargo disponível não interpreta `edition2024`; esse resultado deve permanecer documentado como `blocked-known` e não pode ser escondido para aprovar a release. Warnings de chunks grandes permanecem não bloqueantes quando os gates de build concluem com sucesso.

## Rollback

Antes da criação das tags, o rollback é retornar ao commit anterior ao bump de versão. Depois da publicação, a recuperação deve apontar para `v1.2.6`, sem apagar uma release correta para esconder documentação incompleta. O Service Worker volta a ser invalidado somente por uma nova versão corrigida.

## Critério de publicação final

A 1.2.7 somente poderá receber as tags `v1.2.7` e `desktop-v1.2.7` após: (1) o commit de versão estar na `main`; (2) os gates locais do commit passarem; (3) os workflows remotos aplicáveis terminarem verdes; (4) o Desktop Release concluir nos três sistemas; e (5) os assets e manifestos serem verificados. Até esses fatos existirem, este documento permanece explicitamente em estado `CANDIDATA`.
