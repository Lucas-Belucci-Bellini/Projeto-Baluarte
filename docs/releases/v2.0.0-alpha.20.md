# Baluarte V2 — `v2.0.0-alpha.20`

**Status:** documentação final integrada; tag e release pendentes
**Data:** 2026-08-27
**Marco:** diagnóstico unificado com projeção opcional da saúde do Task Manager

## Resumo

A alpha.20 acompanha uma extensão pequena da fachada `criarPlataforma()`. O diagnóstico agregado da Plataforma V2 passa a expor `trabalho`, uma projeção opcional e somente leitura da saúde do escalonador local do Core. A Plataforma delega a leitura a `Escalonador.saude()`; ela não cria outra fila, não reimplementa Task Manager e não decide políticas operacionais.

A mudança fecha uma lacuna delimitada da faixa de diagnóstico unificado: o retrato da Plataforma já reunia Supervisor, Boot, Registry e lifecycle, mas não permitia observar o escalonador local quando ele fosse injetado pelo consumidor. Sem a opção, o campo permanece `null`, preservando a compatibilidade.

## Segurança e limites

A projeção é read-only e não enfileira, cancela, inicia, para ou reinicia tarefas. Não há retry, backoff, threshold, alerta, SLA, retenção ou nova regra de unhealthy. `readiness` do Task Manager não altera Supervisor, `runtimeAuthority`, permissões, claims, promoção pública ou fallback V1.

A slice não implementa persistência de métricas, dashboards, incidentes operacionais duráveis, retry do Event Bus/Task Manager, filas remotas, Supabase, RLS, Auth, tenancy, ownership, billing, rate limit distribuído, OpenClaw, Hermes, Knowledge Mesh, Risk Engine, aceitação física desktop/mobile ou release estável. A V1, o router, o shell, a sidebar, os wrappers, o Service Worker e os branches concorrentes permanecem fora da mudança.

Esta alpha não fecha a V2. Ela melhora o diagnóstico local do Core e deve continuar sendo interpretada como uma evidência técnica bounded, não como autoridade de produção.
