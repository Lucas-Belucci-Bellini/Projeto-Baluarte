# Release 1.3.4 — Referência visual dourada do JARVIS

**Status:** `CANDIDATA — aguardando CI e publicação das tags`

**Versão web:** `1.3.4`

**Versão do Launcher:** `1.3.4`

## Escopo

A candidata 1.3.4 corrige a composição visual da rota `/jarvis`. A captura limpa do núcleo dourado exibido no navegador foi adicionada como asset local em `public/jarvis/jarvis-nucleo-browser.webp` e passou a ser usada como fallback visual da integração V7. O iframe local `jarvis-nucleo-v7.html` continua sendo o caminho principal, preservando o visual interativo e o contrato same-origin já publicado.

Quando o artefato V7 não estiver disponível, o app não volta a exibir o console visual Mark XIII como composição principal. Ele exibe a imagem de referência dourada fornecida para esta correção; o console Mark XIII permanece montado de forma invisível para preservar seu estado de runtime, telemetria e descarte.

A mudança não altera chat, sessões, modos de IA, memória, observação do Runtime, integração de dados, permissões, Spotify ou Supabase. Não foram adicionados tokens, endpoints externos, captura de áudio, comunicação privilegiada ou dependências de produção.

## Contrato visual e segurança

O adaptador `createJarvisV7Visual()` continua validando somente o artefato local same-origin, rejeitando origem externa, query/hash e protocolos perigosos. O iframe mantém `sandbox="allow-scripts allow-same-origin"`; a imagem de referência é servida pelo próprio bundle e usa `alt` explícito em português.

A captura foi incorporada sem reprocessamento criativo ou alteração de conteúdo. O teste estrutural verifica a presença do asset, o caminho local e a ausência de URL externa no ponto de montagem.

## Publicação e rollback

Esta nota não autoriza a criação de tags. A publicação deverá usar novas tags imutáveis `v1.3.4` e `desktop-v1.3.4`, sem force push, somente após o commit de versionamento passar pelos workflows e pelo smoke externo. O service worker foi avançado para `baluarte-v1.3.4`, impedindo reaproveitamento do cache `baluarte-v1.3.3`.

O rollback continuará sendo feito por novo commit para a release anterior publicada, sem reescrever histórico. A release 1.3.3 permanece imutável.

## Próximo passo
