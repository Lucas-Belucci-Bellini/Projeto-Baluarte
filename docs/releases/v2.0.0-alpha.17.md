**Status:** pré-release técnica publicada

**Marco:** Doctor observa a política local de Module Mode

## Resumo

A alpha.17 torna observável no `verify:v2` o contrato local `module-registry-mode-policy/v1`, integrado anteriormente como fixture determinística e in-memory. O Doctor passa a executar `node scripts/module-mode-policy-check.mjs` como check `safe`/read-only, com o id `module_mode_policy` e categoria `security-local`.

Esta alteração não cria uma segunda política. O verificador reutiliza a fixture canônica de quatro identidades sintéticas e seis casos, enquanto o Doctor somente executa o comando local com timeout bounded e preserva o estado observado. O modo `inventory-only` continua listando o check como `not-run`; o modo normal não converte estados ambientais em sucesso.

## Limites e não-escopo

O check comprova somente a execução local da fixture. Não implementa login, Auth, JWT, claims, service role, Supabase, SQL, migration, RLS, tenancy, ownership, persistência, auditoria remota, retenção operacional, retry, restart, fila, rede, promoção pública ou autoridade server-side real.

O slice não altera V1, router, sidebar, boot, Storage, Evidence, Event Bus, Service Worker, Billing ou qualquer schema externo. Não adiciona dados pessoais, tokens ou segredos. A política real de Module Registry continua dependente de backend protegido, identidades verificadas, staging separado, RLS auditável, auditoria persistente, cleanup idempotente, revisão de segurança, custo e rollback aprovados.

A PR #501 de privacidade permanece separada e não é incluída nesta alpha.17. A PR #471 do Claude Code continua aberta como draft e intocada.
