ARQUITETURA DE MIGRAÇÃO

O padrão que preserva a V1 enquanto a V2 cresce

A implementação muda de lugar, não a superfície de importação. Cada onda fecha somente as fronteiras que realmente consome.

01 · ORIGEM

JS legado

Rotas, testes e consumidores existentes continuam usando o caminho .js.

→
02 · COMPATIBILIDADE

Wrapper .js

Reexporta a implementação canônica e impede uma quebra em cascata nos importadores V1.

→
03 · FONTE DE VERDADE

TypeScript

Fecha estado, DOM, dados e eventos em strict mode, sem duplicar a lógica funcional.

→
04 · EVIDÊNCIA

Fronteira + gates

.d.ts para legado; typecheck, testes, build, smoke e integração para liberar o commit.

A migração não é um rewrite simultâneo; é uma sequência de contratos pequenos, compatíveis e verificáveis.
NUNCA:
• any ou supressões
• relaxar strict
• remover wrappers cedo
• mascarar a dívida V2
