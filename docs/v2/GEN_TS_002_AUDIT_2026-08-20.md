# GEN-TS-002 — Auditoria das fronteiras Node/TypeScript

**Data:** 20 de agosto de 2026

**Autor:** Manus AI

## Objetivo

Auditar a fronteira entre executáveis Node e implementações TypeScript depois da correção histórica `GEN-TS-001`. O foco foi verificar se scripts executados diretamente por Node ainda importam `.ts` sem loader explícito, se os geradores de documentação passam por uma fronteira única e se o backlog deve receber uma correção de código ou apenas uma atualização de estado.

> **Conclusão:** `GEN-TS-001` já está resolvido no main. Os dois geradores auditados executam diretamente com Node por meio de `node --import tsx`, e não foi encontrada outra importação direta de `.ts` em scripts executáveis fora de testes.

## Causa histórica reconciliada

O problema original ocorria porque os geradores `.mjs` atravessavam wrappers `.js` que reexportavam implementações TypeScript, mas eram executados por Node puro. Sem loader, o processo alcançava um arquivo `.ts` e terminava com `ERR_UNKNOWN_FILE_EXTENSION`.

A correção publicada em `GEN-TS-001` criou uma única fronteira operacional em `scripts/lib/run-ts-generator.mjs`. O launcher resolve o alvo, inicia um novo processo Node com `--import tsx`, encaminha argumentos e stdout/stderr e propaga o código de saída. Os geradores canônicos continuam em TypeScript.

O documento histórico `docs/v2/GEN_TS_001_FIX.md` ainda dizia `RESOLVED LOCALLY — PENDING MAIN PUBLICATION`. Essa descrição ficou obsoleta porque o commit corretivo `b8e1db7a` é ancestral do main corrente e a própria baseline registra que os geradores Node-safe passaram no checkout atual.

Eles não são defeitos da fronteira executável porque o runner do projeto fornece o loader TypeScript. A regra é diferente para scripts `.mjs` ou `.js` chamados diretamente por Node.

## Diagnóstico arquitetural

Não existem duas causas independentes nos dois geradores: ambos dependiam da mesma fronteira Node/TypeScript. O runner comum elimina duplicação e mantém o contrato público `.mjs` estável. Reintroduzir `node <arquivo.ts>` diretamente ou remover `--import tsx` reabriria a causa raiz original.

Não foi necessário alterar `strict`, adicionar `any`, introduzir transpile oculto, excluir arquivos do typecheck ou criar um segundo gerador. Nenhum artefato gerado foi editado manualmente nesta auditoria.
